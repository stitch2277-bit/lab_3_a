# Защита лабораторной работы № 3

Вариант 9. Менеджер паролей. Уровень Well-done.

## Демонстрация

1. Запустить PostgreSQL командой `docker compose up -d --wait db`. Открыть браузер и окно PySide6 по командам в [README](README.md).
2. Добавить в веб-версии «Учебная почта» с логином `student@example.test` и вымышленным паролем. В десктопе нажать «Обновить» и показать ту же запись.
3. В десктопе поменять логин, оставив поле пароля пустым. Обновить браузер и показать новый логин. Проверить отображение прежнего пароля кнопкой «Показать пароль».
4. В DBeaver открыть `public.credentials` и `public.activity_log`. Показать шифротекст и события. Можно выполнить запросы ниже.
5. Удалить запись через подтверждение. В другом клиенте обновить список. Показать, что событие удаления осталось в журнале и изменило график. Продемонстрировать меню «Файл → Выход».
6. Открыть пустую форму создания в десктопе и нажать «Сохранить», чтобы показать сообщение проверки. Запустить полный набор pytest.

```sql
SELECT id, title, username, octet_length(password_token) AS token_bytes
FROM public.credentials
ORDER BY id;

SELECT occurred_at, credential_id, title, action
FROM public.activity_log
ORDER BY occurred_at DESC, id DESC;
```

## Как подключена база?

PostgreSQL 17 работает в контейнере из `compose.yaml`. Публикация порта связывает `127.0.0.1:5433` на компьютере с `5432` контейнера. Оба приложения запускаются на компьютере. FastAPI и PySide6 передают вызовы в один класс `PasswordService`, а он обращается к `PostgresRepository`. Подключение выполняется Python-драйвером **Psycopg 3** через `psycopg.connect()`. DBeaver подключается к тому же адресу своим драйвером PostgreSQL через JDBC. [Репозиторий Python](password_manager/repository.py) · [Настройки подключения](password_manager/config.py) · [Документация DBeaver](https://dbeaver.com/docs/dbeaver/Database-driver-PostgreSQL/)

**Откуда берутся таблицы?** Официальный образ PostgreSQL при первой инициализации пустого тома исполняет `db/schema.sql` из `/docker-entrypoint-initdb.d`. Данные записываются в именованный том `postgres_data`. После обычной остановки контейнера данные сохраняются, а скрипт инициализации на уже заполненном томе повторно не выполняется. [Compose](compose.yaml) · [Схема](db/schema.sql) · [Образ PostgreSQL](https://hub.docker.com/_/postgres)

**Зачем две таблицы?** `credentials` хранит актуальные записи. `activity_log` хранит отдельные события с временем, действием, ID и названием записи на момент операции. Внешнего ключа на `credentials` нет, чтобы журнал сохранялся после удаления записи. Ограничение `CHECK` допускает только четыре типа событий.

**Как обеспечена целостность?** Изменение и событие журнала выполняются внутри одного `with psycopg.connect(...)`. Успешный выход фиксирует транзакцию, исключение откатывает её. Параметры SQL передаются отдельно через `%s`. Кавычки в названии остаются частью значения. [Документация Psycopg](https://www.psycopg.org/psycopg3/docs/basic/usage.html)

**Как синхронизируются интерфейсы?** Оба читают одну БД. Каждое обновление заново читает список, журнал и график. Запись появляется в другом клиенте после «Обновить», либо при повторном открытии списка. Таблица и статистика загружаются в одной транзакции с изоляцией `REPEATABLE READ`, чтобы три запроса видели один снимок данных. При параллельном редактировании одних и тех же полей применяется последнее успешно сохранённое значение.

## Какие исключения предусмотрены?

Все ожидаемые ошибки приложения наследуются от `VaultError`. В PySide6 ошибка формы появляется рядом с полями, ошибки операций показываются в диалоге, а ошибка обновления видна в строке состояния. FastAPI превращает ошибки в понятные HTML-страницы или сообщение формы.

| Исключение | Когда возникает | Что увидит пользователь |
| --- | --- | --- |
| `ValidationError` | Пустое обязательное поле, превышение длины, недопустимые символы | Подсказку в форме, HTTP 422 |
| `EntryNotFoundError` | Запись уже удалили в другом интерфейсе или ID отсутствует | Сообщение «Запись не найдена», HTTP 404 |
| `DatabaseError` | Контейнер недоступен, реквизиты неверны или SQL-запрос завершился ошибкой | Сообщение о БД, HTTP 503 |
| `ConfigurationError` | Нет пароля БД, порт вне диапазона или ключ Fernet некорректен | Сообщение при запуске |
| `DecryptionError` | Не совпал ключ или повреждён токен | Сообщение о расшифровке, HTTP 422 |
| `InvalidFormToken` | Отправка веб-формы без актуального CSRF-токена | Просьбу повторно открыть форму, HTTP 403 |

`InvalidToken` библиотеки cryptography преобразуется в `DecryptionError`. `psycopg.Error` преобразуется в `DatabaseError`. FastAPI также обрабатывает неверный формат параметра маршрута через `RequestValidationError`. [Классы ошибок](password_manager/errors.py) · [Обработчики FastAPI](password_manager/web.py)

## Чем похожи и различаются интерфейсы?

| Элемент | PySide6 | Веб-версия |
| --- | --- | --- |
| Главное окно и меню | `QMainWindow`, `QMenuBar`, `QAction` | HTML-страница, `nav`, раскрывающийся блок `details` |
| Таблица | `QTableWidget`, третья колонка с кнопками | HTML `table`, кнопки и ссылки в третьей колонке |
| Поля и форма | `QDialog`, `QFormLayout`, `QLineEdit` | Страница Jinja2 с `form`, `label`, `input` |
| Пароль при вводе | `QLineEdit.EchoMode.Password` | `input type="password"` |
| Действие кнопки | Сигнал `clicked` вызывает метод Python | Браузер отправляет HTTP-запрос, FastAPI вызывает обработчик |
| График | Семь горизонтальных `QProgressBar` | Семь HTML-элементов `meter` |
| Журнал | `QListWidget` | Список HTML `ul` |
| Выход | Закрывает окно | Открывает страницу завершения работы. Остановка сервера выполняется из терминала |

**Почему элементы похожи?** В обеих версиях сохранены тот же порядок блоков, названия и шаги работы. Можно показать одно действие и объяснить, какой виджет или HTML-элемент его реализует. Методы `create`, `update`, `reveal` и `delete` одинаковы для обоих интерфейсов.

**Какие инструменты можно было взять?** В рамках PySide6 окно можно собрать в Qt Designer, а поведение кнопок оставить в Python. Для десктопа на других условиях подошёл бы Tkinter с `ttk.Treeview`. Для веба по методичке допустим Django, если нужны встроенные ORM, формы и административный интерфейс. Здесь FastAPI и Jinja2 дают локальный веб-интерфейс с несколькими HTML-формами. График можно построить через Matplotlib, если понадобятся оси, несколько рядов данных или экспорт. Текущий график показывает одну величину и помещается в семь простых полос. [Qt Widgets Designer](https://doc.qt.io/qtforpython-6/tools/pyside-designer.html) · [FastAPI Templates](https://fastapi.tiangolo.com/advanced/templates/)

**Где здесь ООП?** `MainWindow` наследуется от `QMainWindow`, а `EntryDialog` от `QDialog`. Интерфейс получает объект `PasswordService` через конструктор. Этот объект содержит репозиторий и шифр. Репозиторий хранит параметры подключения, шифр хранит объект Fernet. У каждого класса своя ответственность.

## Пароли и активность

**Почему шифрование?** Менеджер должен показать исходный пароль, поэтому используется обратимое аутентифицированное шифрование Fernet. Хеш подходит для проверки пароля при входе, где исходное значение восстанавливать не требуется. Ключ хранится в `.env`. База хранит токен в `BYTEA`. Потеря исходного ключа делает старые записи нечитаемыми. У этого учебного приложения один локальный пользователь и нет отдельного входа. [Документация Fernet](https://cryptography.io/en/latest/fernet/)

**Что попадает в журнал и как строится график?** Журнал отображает 20 последних успешных действий. Для графика SQL считает все события по календарным дням UTC, независимо от лимита журнала. Пропущенные дни получают ноль. Добавление, изменение, явный просмотр пароля и удаление учитываются. Простое обновление экрана событий не создаёт. Пароль и токен в журнал не записываются.

**Зачем POST при показе пароля?** Действие добавляет событие в журнал. Пароль передаётся в теле HTML-ответа с заголовком `Cache-Control: no-store`. Показ требует токен формы, как и остальные POST-действия. Список и форма редактирования получают только метаданные записи.

**Почему при изменении можно оставить поле пароля пустым?** Пустое поле говорит сервису сохранить текущий токен. SQL выполняет `COALESCE(новый_токен, password_token)`. Это позволяет поменять логин или название без раскрытия пароля.
